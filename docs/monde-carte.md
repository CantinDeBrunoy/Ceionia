# Le monde : la carte

> Fichiers : `src/world/world.ts` (classe `World` : grille, couches, relief affiché, sauvegarde), `src/world/mapgen.ts` (`newWorld`, décors d'office, pétrole), `src/world/continent.ts` (plan et hauteurs du continent, climat), `src/world/noise.ts` (bruit simplex), `src/world/terraform.ts` (pinceaux, effet sur la grille), `src/render/terrainView.ts` (maillage du sol), `src/world/ferry.ts` (traversée vers l'île).
> Tests : `tests/place.test.ts`, `tests/rivage.test.ts`, `tests/curves.test.ts`, `tests/ferry.test.ts` (tous appellent `setMapSize(192)` puis `syncChunks()` avant `new World()`).
> Voir aussi : [eau-rivieres.md](eau-rivieres.md), [vegetation-biomes.md](vegetation-biomes.md), [outils-terrain.md](outils-terrain.md), [sauvegarde.md](sauvegarde.md), [portail-ile.md](portail-ile.md), [architecture.md](architecture.md)

## En bref
La carte est une grille de `N × N` cases ; le relief est défini sur les `(N+1)²` sommets de cette grille. Chaque case porte des couches parallèles (route, végétation, bâtiment, décor…). Une seule carte est jouable, le « Continent » (`MAPS` dans `mapgen.ts`, 192 cases de côté), tiré d'une graine : relief, climat, forêts, lacs, grottes, pétrole et île du portail en découlent. Le joueur modifie ensuite le relief (sculpture, bâtiments qui aplanissent) ; seul le relief brut est sauvegardé, tout le reste de ce qui est « visuel » se recalcule.

## Règles du jeu
- Taille : `MapDef.size` = 192 pour une nouvelle partie du Continent (`MAPS`) ; `MapDef.sizes` = `[192, 320]`, les tailles qu'une sauvegarde peut avoir. Une partie garde la taille qui l'a créée : `playSize(carte, n de la sauvegarde)` (`mapgen.ts`) la donne à `setMapSize` dans `main.ts` › `start`. Id de carte `CONTINENT = 3` (numéro des sauvegardes d'origine ; une carte inconnue retombe sur lui dans `main.ts`).
- Hauteurs : `MIN_H = -2.4`, `MAX_H = 16`, mer à `SEA = 0` (`world.ts`). Les pinceaux et le générateur écrêtent à ces bornes.
- Repères d'altitude (`world.ts`) : `MOUNTAIN_H = 2.4` (on est « dans la montagne » : mine, carrière, club alpin), `TREE_LINE = 5.8` (plus d'arbres posés par le générateur au-dessus), `SNOW_LINE = [7, 8.2]` (neiges éternelles, fondu), `ALPINE_PEAK = 5.2` et `ALPINE_REACH = 7` (station de ski : un sommet d'au moins 5,2 à moins de 7 cases).
- Aucun brouillard de guerre : toute la carte est visible dès le départ. La brume affichée est météo (`fogLevel` dans `main.ts`), voir [ciel-meteo.md](ciel-meteo.md).
- Début de partie : `World.startSpot()` cherche la place 3 × 3 libre la plus proche du centre ; `clearStart` (`mapgen.ts`, version 3) y retire arbres et rochers.

## Fonctionnement dans le code

### Grille et couches (`World`)
Index d'une case : `ci(x, z) = z * N + x` ; d'un sommet : `vi(x, z) = z * (N + 1) + x`. Une case `(cx, cz)` a pour coins les sommets `(cx..cx+1, cz..cz+1)` (`cellCorners`, `cellAvg`, `cellMin`, `cellSlope`).

| Couche | Type | Sens |
|---|---|---|
| `heights` | `Float32Array (N+1)²` | relief de jeu (sauvegardé × 100, arrondi) |
| `occ` | `Int32Array N²` | id du bâtiment qui couvre la case (0 : libre) |
| `road` | `Uint8Array` | 1 : route (courbes : `curves`, voir [routes.md](routes.md)) |
| `veg` | `Uint8Array` | 0 rien, `VEG_FOREST` 1, `VEG_FIELD` 2, `VEG_GARDEN` 3 (anciens jardins, effacés au chargement), `VEG_ROCKS` 4, `VEG_CAVE` 5, `VEG_WRECK` 6, `VEG_VOLCANO` 7, `VEG_FISSURE` 8 ; `>= VEG_CAVE` = décor unique |
| `decor` | `Uint8Array` | emprise (déborde de la case) d'une grotte ou d'une faille ; recalculé par `computeDecor` |
| `paving` | `Uint8Array` | 1 : case pavée, un habillage du sol sous les bâtiments et les routes (`setPaving`, `pavingVersion`, vue `PavingView`) |
| `biome` / `biomePaint` | `Uint8Array` | biome de la case ; peinture du joueur (0 : climat, sinon biome + 1) |
| `lake`, `lakeLevel` | `Uint8Array`, `Float32Array` | lacs, calculés par `Streams` (voir [eau-rivieres.md](eau-rivieres.md)) |
| `waterDist` | `Uint8Array` | distance à l'eau en cases (0 = eau, plafonnée à 12 puis 255) |
| `basalt`, `ash` | `Float32Array`, `Uint8Array` | coulées de lave refroidies (voir [outils-terrain.md](outils-terrain.md)) |
| `oil` | `Uint8Array` | gisements de pétrole (au sol, un violet sombre et des taches de brut, `OIL_SOIL` / `OIL_TAR` de `terrainView.ts`, avec les flaques d'`oilSeeps.ts` ; violets aussi sur la mini-carte, même sous les arbres. Brun sombre jusqu'au 22 nov. 2026 : on ne les trouvait pas) |
| `grazed`, `bloom` | `Float32Array` | vie sauvage, non sauvegardée |

Le champ `World.n` vaut `N` à la construction. `N` et `VS` sont des `let` exportés : `setMapSize(n)` les change et doit être appelé **avant** de construire `World`, les vues, la caméra (`main.ts` le fait au démarrage, avec la taille de la sauvegarde pour une partie reprise, puis `syncChunks()` de `vegetation.ts`). `genHeights(carte, graine, gen, n)` prend le côté en paramètre (`newWorld` passe `N`). Valeur par défaut `N = 96` : sans `setMapSize(192)`, un test échoue de façon obscure.

Marqueurs de travail pour la vue : `terrainDirty` / `terrainRect` (`markTerrain`, `markTerrainAll`, `takeTerrainRect`), `vegDirty` / `vegRect` (`markVeg`), `roadsDirty`, `version` (toute modification structurelle ; la simulation et les ponts en dépendent), `visVersion` (relief affiché refait).

### Relief affiché (`vis`)
La vue ne dessine pas `heights` mais `vis`, grille `VS × VS` avec `VR = 2` sous-sommets par case (`VS = N*VR + 1`). `World.updateVis(rect)` :
1. `computeBiomes` puis `computeDecor` ;
2. suréchantillonne `heights` en interpolation bilinéaire ;
3. épingle (`visPin`) les sous-sommets sous les bâtiments : ils restent plats ;
4. `VIS_PASSES = 3` passes de flou binomial 3 × 3 (sauf épinglés) ;
5. le lissage s'estompe en altitude (au-dessus de 3, plein à 6) et au bord des à-pics (écart > 0,35) pour garder crêtes et falaises franches ;
6. `carveRavines` (failles, creusées dans `vis` seulement, `ravine` 0..1) puis `raiseCaveKnolls` (buttes des grottes).
Avec `rect` (en cases), seule la fenêtre retouchée plus deux cases de marge est recalculée (`visWindow`).

Le maillage du sol (`TerrainView`) : des sommets non indexés, 6 par sous-case, rangés par lignes de sous-cases (`topGeo`, jamais dessinée elle-même). Il est découpé en tuiles de `TILE` = 64 cases (`TerrainView.top`, un groupe) : chaque tuile partage les attributs de `topGeo` (un seul tampon sur la carte graphique) et n'a que son index et une boîte de toute la hauteur possible. three élague ainsi les tuiles hors du champ et de la carte des ombres. 9 tuiles à 192, 36 à 384 ; à 384, de près, 15 tuiles dessinées sur 36. `hAt` lit `vis` (même découpage en triangles que le maillage) ; `rawAt` lit `heights` (utilisable avant le premier `updateVis`). **La logique de jeu lit surtout `heights` via `cellAvg`/`cellMin`/`cellSlope` ; le rendu, la marche des habitants (`surfaceAt`) et le placement des modèles lisent `hAt`.** Les deux peuvent différer de quelques centièmes.

### Génération (`newWorld` dans `mapgen.ts`)
Versions du générateur (`continent.ts`) : `GEN_FIXED = 1` (agencement fixe, d'avant le plan), `GEN_PLAN = 2` (agencement tiré de la graine), `GEN_VAR = 3` (plan plus libre, huit orientations, lacs et forêts variables), `GEN_ARCH = 4` (l'archipel, seulement par l'agrandissement d'une partie, voir plus bas), `GEN_SLOTS = 5` (comme la 3, mais les contrées changent de place : `slots`). `GEN = GEN_SLOTS` pour les nouvelles parties. **La 4 n'est pas un continent plus récent que la 3** : tester `gen === GEN_ARCH` pour l'archipel, et `mainGenOf(gen, mainGen)` pour la version du continent (les étapes « version 3 » de `newWorld` valent pour 3, 4 et 5 : `gen >= GEN_VAR`) ; `newWorld(world, mapId, seed, gen = GEN_PLAN)` : **sans `gen`, c'est la version 2 (continent de référence des tests, qui ne doit plus bouger)** ; `main.ts` passe `GEN` pour une partie neuve.

Étapes de `newWorld` :
1. `genHeights` : bruits `Simplex(seed)` et `Simplex(seed*7+13)` ; chaque sommet prend `plannedHeight(toPlan(orient, x, z))` (version 1 : `fixedHeight`), écrêté à `[MIN_H, MAX_H]`. `world.restore(...)` installe la grille.
2. `computeBiomes`, `shapeBiomes` (mares de marais, dunes de désert, voir [vegetation-biomes.md](vegetation-biomes.md)), `computeBiomes` à nouveau.
3. Forêts et rochers par case (bruit `Simplex(seed+99)`, densité par biome) ; version 3 : `addGroves` (8 à 23 bosquets). Détail dans [vegetation-biomes.md](vegetation-biomes.md).
4. `world.sanitize` (retire la végétation que la pente interdit).
5. Volcan : `raiseVolcano(world, …, 5.5)` au centre de la contrée « île volcanique » du plan (`fromPlan` le remet dans le repère de la carte).
6. Lacs de montagne : `carveTarns` (version 3 : 2 à 7 cuvettes entre les hauteurs 4 et 8,5, puis 0 à 4 étangs entre 1 et 3,2 ; version 2 : 5). Voir [eau-rivieres.md](eau-rivieres.md).
7. `addDefaultDecor` : grottes (2 au plus, espacées de 30), failles (5, espacées de 20), épaves (3, espacées de 14), puis `addOilFields` (`OIL_FIELDS = 7` nappes dont `OIL_DRY = 3` d'abord en désert ou marais, `OIL_SPACING = 26`).
8. `addPortalIsland` (si plan) : île du portail au large (voir [portail-ile.md](portail-ile.md)).
9. Version 3 : `clearStart`.

### L'archipel (version 4, `archipelago.ts`)
Sur une carte de `ARCH_N` = 384 cases, une partie neuve prend la version `GEN_ARCH` = 4 (`main.ts` : `N >= ARCH_N`) ; les nouvelles parties restent à 192 (`MapDef.size`) tant que l'archipel n'est pas ouvert aux joueurs. `archLayout(seed)` (mis en cache par graine et taille) tire la place des îles, dans un repère où l'île principale est à l'ouest, puis le tourne ou le retourne (huit orientations) :
- **île principale** : le continent de la version 3, à sa taille d'origine, dans un cadre de `MAIN_N` = 192 cases (`mainFrame(gen, seed, n)` ; toute la carte avant la version 4). Plan, climat (`fillClimate`), rivière (`riverCourse`), lit de cailloux (`fillRiverBed`), volcan, départ (`startSpot`, au milieu du cadre) et île du portail (cherchée dans le cadre) se calculent dans ce cadre. Canyon, grottes, failles et pétrole restent dans le cadre (`World.inMain`) ;
- **deux îles rivales** (`rivals`), chacune l'union de 3 à 5 lobes (`lobes`, le premier au centre porte le village ; distance au bord `lobeT`, rayon déformé par un bruit), agrandis ou réduits jusqu'à `RIVAL_LAND` = 11 900 cases de terre (la moitié de l'île principale), séparées par un bras de mer (36 à 73 cases mesurées) : peuple `orient` (climat chaud et sec : sable, palmiers) et peuple `asie` (tempéré humide, pitons rocheux escarpés loin du village ; l'île orientale a une longue arête rocheuse). Chacune a la place de son village (`village`, rayon 15, à 0,42 fois le rayon de l'île vers le bras de mer, la côte à 15 à 32 cases du centre) : à 1,3, tout plat au cœur (0,6 fois le rayon), gardant 30 % du relief vers le bord (un point haut pour le palais), raccordé en 8 cases ; aplanie par `flattenVillages` après les dunes, les forêts et les étangs ;
- **une à trois petites îles** (`small`), rayon 16 à 22, tropicales ;
- **toutes petites îles** (`tiny`, `drawTiny`, `tinyHeight`) : jusqu'à 70 rochers, îlots de 1 à 6 cases, bancs de sable allongés et atolls (anneau de récif, lagon à -0,6, climat tropical pour les coraux), gardés surtout près des côtes des îles (entre 1,15 et 1,8 fois leur bord), rarement au large, jamais dans le cadre de l'île principale.
- **climat du large** (`isleClimate`) : tempéré et sec, sous les seuils des tropiques et du marais. Sinon l'eau prend par plaques la teinte du marais et des récifs de corail y poussent ; le climat d'une île ne déborde que jusqu'à sa côte.
Le relief (`archHeights` dans `mapgen.ts`) : le fond du large partout à `SEA_FLOOR` (-1, la profondeur de la mer de décor, qui reste plate sur cette carte : `marginDeep`) : une seule mer, la teinte de l'eau ne change qu'aux abords des côtes ; la pleine mer du continent (-1 et plus bas) y est ramenée, ses rivières, lacs et hauts-fonds ne bougent pas ; le continent dans son cadre (sa mer descend au fond du large : pas de carré visible), les îles (`isleHeight` : plateau vallonné, côte déformée), puis la mer sur les 4 cases du bord. `World.isles` est tiré de la graine au chargement et écrit dans la sauvegarde (`isles`) pour qui la lit au dehors. Tests : `tests/archipel.test.ts`. Sur le replat de chaque île rivale, la ville de décor de son peuple : voir [iles.md](iles.md). Entre les deux îles rivales, le conflit vivant (escarmouches, commerce, patrouilles) : voir [trafic.md](trafic.md).

### Explorer le monde : l'archipel en option (`expand.ts`, `ui/worldChoice.ts`)
Toutes les parties commencent sur la carte de 192. L'archipel est l'une des deux voies du grand choix de la fin de l'Antiquité (voir [grand-choix.md](grand-choix.md)) : « Explorer le monde » sur la carte du choix, ou plus tard dans l'onglet « Grands choix » des expéditions (au bac à sable, tout de suite). Rien n'y pousse : plus de ligne en tête du rayon Production. `Game.exploreWorld` joue une cinématique qui fait office d'écran de chargement : un film enregistré (une caravelle en mer, puis la brume) pendant lequel la partie est sauvegardée, agrandie par `expandWorld` puis rechargée ; il reprend après le rechargement et couvre le chargement (`LoadingScreen` en mode traversée). Détail des plans : [grand-choix.md](grand-choix.md). `World.explore` (`'no'` : l'ancienne carte « Rester sur mon île ») n'est plus lu, seulement relu et réécrit.

`expandWorld(sauvegarde du monde, carte, graine)` : le continent sur 192, quelle que soit sa version (`canExpand`). L'île garde la version de son générateur (`World.mainGen`, sauvegardé si ce n'est pas la 3) : `mainGenOf(gen, base)` donne au plan, au climat (`fillClimate`), à la rivière (`riverCourse`, courant de `flow.ts`) et au lit de cailloux (`fillRiverBed`) la version d'origine de l'île ; sur une ancienne carte figée (version 1), pas de `fixIslets`. Il génère une partie neuve de l'archipel pour la graine, puis pose l'ancienne île dans le cadre de l'île principale : relief (tel quel ; seule sa pleine mer descend au fond du large, voir plus bas), routes, végétation, biomes peints, défrichages, failles, lave, cendres, pétrole, torches, bâtiments, points de passage des trains, routes en courbe, île du portail et démons d'une vague en cours, tous décalés du coin du cadre. Hors du cadre, la mer et les îles de la partie neuve. `archipelagoOn(world)` (`expand.ts`) dit si l'archipel est ouvert ; `World.exploredAt` garde l'âge où le joueur a accepté (sauvegardé). La sauvegarde reçoit `reveal` : à l'arrivée, le survol en direct de la cinématique (`Game.revealIsles`, `voyageStage.ts`), une fois tout prêt et le film fini : la brume se dissipe, l'horizon recule, les deux îles rivales, leurs deux flottes face à face, puis le retour au village ; il appelle `Game.onIslesRevealed` (la carte du choix de l’allié, voir [diplomatie.md](diplomatie.md)). Tests : `tests/agrandir.test.ts` (village intact et décalé, biomes identiques à plus de 99 %), `tests/agrandirCote.test.ts` (une côte bâtie jusqu'au bord de l'ancienne carte : relief, eau et occupation identiques ; réparation d'une partie abîmée).

**Le relief de l'île ne bouge pas** (bug de l'auteur, 21 nov. 2026 : après la traversée, une presqu'île bâtie à l'ouest du village était « en bazar », palissades et pontons dans la mer, pilotis seuls, un bâtiment au bord d'une falaise, des gradins gris autour). `expandWorld` fondait le relief des 12 dernières cases de l'ancienne carte vers celui d'une partie neuve de l'archipel, en les croyant déjà en mer : une terre près du bord s'enfonçait, ou montait en gradins vers la terre de la carte neuve, et tout ce qui y était posé restait en place. L'auteur l'a précisé : « les zones abîmées sont celles que j'avais terraformées ». En plus de la bande du bord, toute mer sous -1 du cadre allait vers le relief de la carte neuve, souvent de la terre : un bassin creusé se comblait. Désormais, le continent tel que généré est refait à l'agrandissement : tout sommet que le joueur a retouché (sculpté, aplani sous un bâtiment, creusé pour un port) garde exactement sa hauteur, ainsi que tout sommet qui n'est pas en pleine mer (sous `OPEN_SEA` = -0,5, lui et ses voisins à deux sommets). Seule la pleine mer jamais retouchée peut descendre vers le fond du large, jamais monter. La sauvegarde agrandie porte `coast` (`World.coast`).
- **Couches oubliées** : les pavés (`paving`), le cap des grottes (`caveYaw`) et le fer céleste (`starIron`) n'étaient pas décalés : ils restaient aux cases de l'ancienne carte, ailleurs sur la grande. Ils le sont.
- **Les parties déjà abîmées** (agrandies avant, sans `coast`, `exploredAt` connu) sont réparées une fois au chargement (`repairCoast`, appelé par `Game` avant `World.fromJSON`) : la carte neuve de l'archipel se refait depuis la graine, et l'ancien relief se retrouve en défaisant le fondu (`h = lerp(neuve, ancienne, w)`, `w` connu d'après la distance au bord). Sur les deux sommets du bord même, `w` est trop petit : c'est le relief du continent d'origine, refait lui aussi, et ce que le joueur y avait sculpté est perdu. Seules la terre, la côte et les hauts-fonds sont rétablis. Un bassin creusé sous -1,1, partout dans le cadre, avait pris la hauteur de la carte neuve : on le reconnaît (son voisinage 3 × 3 vaut exactement la carte neuve, le continent d'origine y était plus haut) et il redevient une eau profonde (-1,1), sa profondeur exacte étant perdue. Les bassins des ports se recreusent d'eux-mêmes au chargement (`repairFootprints`). Les pavés, caps de grottes et fer céleste déjà mal placés ne se réparent pas. Un relief retouché par le joueur après l'agrandissement, dans cette bande, peut ne pas se réparer exactement. Coût : les deux générations, une fois (quelques secondes au chargement).

### Le plan du continent (`continentPlan(seed, gen)`)
**Version 5 (`slots`)** : après le tirage des contrées (tailles, formes, axes comme en version 3), leurs places changent : le massif sur un côté du nord (la rivière en descend vers le sud), l'île volcanique et l'archipel dans les deux coins du sud (dans un ordre ou l'autre), puis, hors du couloir de la rivière (sous le massif) : les mesas au chaud (est ou sud, loin de l'archipel), les plateaux vers les bords, le lac au cœur des terres. Un tirage où deux contrées des terres se chevauchent (plus que dans la version 3) est refait ; la rivière se retire jusqu'à 30 fois (embouchure dans le couloir) avant de refaire tout le tirage ; jusqu'à 400 essais. Mesuré : aucun plan de secours sur 300 graines, 48 dispositions (à multiplier par les huit orientations). Tests : `tests/contrees.test.ts`.

Le plan est un jeu de « contrées » `Zone { u, v, r, a, e }` (centre en part de carte, rayon, axe, étirement) : côte (ellipse déformée avec caps et baies), montagnes (chaîne et sommets `peaks`), plateaux en gradins, grand lac et îlot, île volcanique et détroit, mesas, archipel, rivière (`riverU`), vent (oriente les dunes), `orient` (0 à 7 : bit 1 miroir est-ouest, bit 2 miroir nord-sud, bit 4 échange des axes ; `toPlan` / `fromPlan`). Le tirage est refait jusqu'à 100 fois tant que `fits(plan)` est faux (lac fermé, massif dans les terres, archipel au large, rivière qui ne frôle ni lac, ni mesas, ni île) ; sinon `SAFE_PLAN`. Générateurs aléatoires : `mulberry32(seed*991 + 7121)` (version 3) ou `seed*977 + 4049` (version 2).

`plannedHeight` empile, dans l'ordre : relief de fond (`relief` ou `RELIEF0`), montagnes, plateaux, mesas, lac, collines de l'île volcanique, mer autour (`d` côte), rive du lac, détroit, île, archipel, vallée de la rivière, puis (version 3) une **marge de mer bruitée** (`EDGE_SEA` = 0,083 du côté, de 0,05 à environ 0,17 selon un bruit de baies et d'anses, distance au bord elle-même déformée) : la terre, montagnes comprises, s'enfonce avant le bord, et la côte se dentelle au lieu d'être tranchée droit. Enfin la mer sur les 4 cases du bord (toutes versions). Le continent des versions 2 et 3 déborde de la carte (ellipse jusqu'à 0,47 de rayon, caps, déformation) : sans la marge, la bande du bord le coupait à la règle (40 graines sur 40). Test : `tests/cotes.test.ts`. L'ordre compte : un ajout au milieu change les contrées d'après.

### Cases et emprises
- `canPlace` (voir [placement-construction.md](placement-construction.md)) : refus sur `occ`, `road`, `decor`, `lake`, eau trop proche (`cellMin < 0.05`), pente (`mx - target > 0.85 * s * steep`).
- `place` aplanit l'emprise à `flatTarget` (moyenne, ou hauteur des coins déjà tenus par un voisin) ; `vertexHeld` : un sommet partagé avec un autre bâtiment n'est pas touché. `removeBuilding` ne remet pas le relief d'origine.
- Grottes et failles : `decorCells` (disque `CAVE_R = 1,15` ; faille : sillon sinueux de 7 à 10 cases de long), `decorFits`, `setVeg`.

## Pièges et invariants
- **Sauvegarde** : `toJSON` écrit `n`, `gen`, `heights` (×100), routes, `veg` (paires case, type), biomes peints, bâtiments, lave, pétrole, courbes… `fromJSON` refuse (`Sauvegarde incompatible`) si `d.n !== N` ou si la taille de `heights` diffère. Pas de `gen` dans la sauvegarde : version 1. Le climat (donc les biomes) se recalcule depuis `mapId|seed|gen` (`computeBiomes`, clé `climateKey`) : **changer `fillClimate` ou `continentPlan` pour une version existante modifie les biomes des parties en cours**. Pour changer le générateur, créer une version (`GEN_xxx`), garder les anciennes branches telles quelles.
- Le relief arrondi au centième à la sauvegarde : `addOilFields` classe les cases par un rang tiré de la graine (pas par un tirage en suite) pour retrouver les mêmes nappes.
- `addDefaultDecor` est rappelé à chaque chargement (`main.ts`) et n'ajoute un type que si **aucune** case de ce type n'existe : un joueur qui a effacé toutes ses grottes les retrouve au prochain chargement (à vérifier : probable). Même règle pour le pétrole (`oil.includes(1)`).
- Plusieurs définitions de « case d'eau » coexistent, avec des seuils différents (voir le tableau dans [eau-rivieres.md](eau-rivieres.md)) : `isWaterCell` (< 0,08), `nearWater` / `waterNear` (< -0,05), `isWet`, `realWater`. Ne pas les unifier sans relire les appelants.
- Écrire dans `heights` sans `markTerrain` ni `sanitize` laisse routes et végétation invalides et le rendu périmé. Écrire dans `veg`/`road` sans `markVeg` / `vegDirty` / `roadsDirty` : la vue ne se refait pas.
- `updateVis` pilote aussi biomes et décor : un relief changé sans passage par `TerrainView.update` laisse `biome`, `lake` et `decor` anciens.
- Bâtiments : `repairFootprints` (au chargement) réaplanit les emprises devenues non planes et approfondit le bassin du port ; un port garde son quai à `QUAY_MAX = 0,32` au plus.
- Les cartes d'avant (île, vallée, plateaux) n'existent plus ; `mapDef` renvoie `null`.

## Pour modifier
- **Changer la taille** : `MAPS[0].size` (nouvelles parties), et l'ajouter à `MAPS[0].sizes` en gardant les anciennes tailles (sinon leurs sauvegardes sont refusées) ; vérifier `CH` dans `vegetation.ts` (tuiles de 32 au-delà de 128), `MAX_TORRENTS` et `keep` des lacs dans `streams.ts` (proportionnels à `N`), les tests (`setMapSize`, `tests/tailleCarte.test.ts`). Une sauvegarde d'une taille absente de `sizes` est refusée (`validate`, puis `d.n !== N` dans `fromJSON`).
- **Nouvelle contrée ou nouvelle forme** : nouvelle version `GEN_xxx` dans `continent.ts`, branche dans `continentPlan` / `plannedHeight` / `fillClimate`, la valeur de `GEN`, `genHeights` et `newWorld` (étapes dépendantes de `v3`). Ne pas modifier `GEN_PLAN` (tests).
- **Nouvelle couche par case** : champ dans `World`, `toJSON` / `fromJSON` avec valeur par défaut, `restore` si elle est dans les annulations (`Snapshot`), marqueur de rafraîchissement.
- **Nouveau décor unique** : constante `VEG_xxx` (>= `VEG_CAVE` s'il est « spécial »), `vegFits`, `pick` dans `addDefaultDecor`, rendu dans `VegView.rebuildSpecial`.
